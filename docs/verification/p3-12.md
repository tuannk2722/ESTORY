## Kết quả triển khai

- `/admin/effects` dùng AdminShell hiện có, có search/category/status/cursor, desktop
  table, mobile cards, loading/empty/error, drawer chỉnh metadata/trạng thái và keyword
  CRUD. Technical ID/category chỉ đọc; không có Create Effect, renderer/default/per-picker
  controls.
- Drawer dùng renderer thật cho Preview/Stop, tôn trọng effective reduced-motion từ
  `ThemeProvider`, trap/return focus, error summary liên kết field và confirm khi đóng dữ
  liệu bẩn. `409 STALE_UPDATE` giữ drawer, khóa mutation cũ và yêu cầu tải revision mới.
- `EffectCatalogService` merge technical manifest trong code với overlay/keyword trong DB.
  Admin nhận capabilities rõ ràng; Author chỉ nhận effect/keyword active một lần trong
  editor aggregate. Runtime suggestion dùng dictionary từ payload, không còn import mảng
  seed cứng vào client.
- Effect inactive bị ẩn khỏi block/Scene picker, preset mới và suggestion; cấu hình đã lưu
  vẫn có presentation fallback để chỉnh sửa và Reader tiếp tục render qua manifest/registry,
  không gọi catalog hay kiểm `is_active`.
- Admin mutations dùng strict Zod, same-origin, exact-admin check trong transaction,
  conditional `EffectDefinition.updatedAt` cho lost-update và unique normalized keyword.
  Sau commit chỉ ghi structured server log gồm action/actor/effect/keyword ID/revision; không
  chứa label, description, keyword, token, SQL hay content.
- Deployment command `pnpm effects:sync-manifest` chạy trong Serializable transaction,
  fail khi DB có technical ID lạ, chỉ tạo overlay còn thiếu và chỉ seed keyword cho overlay
  mới. Rerun không ghi đè metadata hoặc phục hồi keyword Admin đã xóa.

## Runbook cutover và cleanup audio

Đây là **data migration sau deploy**, không phải Prisma schema migration. Không sửa SQL
migration đã áp dụng và không chạy full `migrate:phase3` trên DB đang có chỉnh sửa Admin.

1. Build/test code mới. `effects:sync-manifest` chỉ seed tập Admin, vẫn chấp nhận dòng audio
   legacy để instance cũ không bị hỏng trong rolling deploy. Catalog/service mới không dùng
   metadata/status/keyword của dòng này. DB mới không tạo audio ngay từ đầu.
2. Deploy code mới và dừng instance/job/preview cũ dùng chung DB. Xác minh editor load/save
   audio block/scene, API Admin từ chối audio, Reader giữ snapshot. Không rollback code cũ
   sau bước cleanup nếu chưa phục hồi overlay từ backup.
3. Chọn đúng DB qua cấu hình môi trường của repo. Chạy `pnpm effects:retire-audio` để dry-run
   (chỉ log số overlay/keyword). Sau đó chạy:

   ```text
   pnpm effects:retire-audio --apply --backup <đường-dẫn-file-backup-mới-ngoài-git-và-public>
   ```

   Parent directory phải tồn tại; file được tạo exclusive, không overwrite. Backup chứa
   toàn bộ overlay/revision và keyword con, không chứa URL DB/token. Không commit/publish file.
   Backup được ghi trước delete trong transaction Serializable; lỗi backup không xóa DB.
   Nếu transaction fail sau khi ghi file, giữ file đó để đối chiếu và dùng tên mới khi retry.
4. Xác minh overlay audio và keyword con bằng 0; chạy lại cleanup phải trả 0/0, chạy lại
   `effects:sync-manifest` không tạo audio. Không xóa audio instances, Scene JSON, AudioAsset
   hay media. Không xóa file preset chỉ vì ngừng cung cấp lựa chọn mới.
5. Rollback về code cũ: trước khi chuyển traffic, phục hồi `overlay` trong JSON backup thành
   `EffectDefinition` (bỏ field `keywords`) và các keyword con trong cùng transaction; giữ
   ID/normalizedKeyword/weight/timestamp. Nếu DB mới chưa từng có overlay, seed audio từ
   phiên bản cũ. Không chạy seed cũ toàn bộ để phục hồi vì có thể tái tạo keyword Admin đã xóa.

Trạng thái đích không giữ overlay audio. Việc chấp nhận dòng legacy là hỗ trợ nâng cấp từ
phiên bản trước, không phải nguồn quyền quản lý thứ hai. `migrate:phase3 -- --mode=verify`
đối chiếu overlay với tập Admin, vì vậy DB legacy chưa cleanup không đạt parity đích.

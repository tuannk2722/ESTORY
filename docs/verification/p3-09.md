# P3-09 — R2 media storage

Ngày kiểm tra: 2026-09-09. Starting HEAD: `6d5fcda`, branch `phase3`.

**Trạng thái:** foundation/API và kiểm thử Local + Neon dev + live R2 đã hoàn tất.
GitHub Actions, Vercel preview/production và các UI/domain claim stage sau chưa được
suy là hoàn tất từ kết quả này.

## Phạm vi implementation

- Chốt tài liệu trước code: R2 Standard sau `MediaStorageProvider`; image/poster
  5 MiB, audio 8 MiB/5 phút, background video `mp4`/`webm` 50 MiB cho Admin và
  Author. Author có 10 retained personal-video slots; AI vẫn chỉ sinh ảnh tĩnh.
- `MediaUpload` lưu intent bền vững với owner, purpose, server-generated object key,
  expected metadata, video slot, result và state
  `PENDING → PROCESSING → COMPLETED/REJECTED/EXPIRED`; `CLAIMED` dành cho stage domain.
  Hai migration additive tách việc tạo enum/table và thêm `PROCESSING`.
- Presign tạo row trước khi trả PUT URL 10 phút. PUT ký `Content-Type`, immutable
  `Cache-Control` và `If-None-Match: *`; client không quyết định owner/key/limit.
  Key chứa hash owner, không lộ user ID, và replace luôn cần UUID/key mới.
- Complete đọc HEAD + byte range/object, đối chiếu exact size/content type rồi
  kiểm magic bytes, image dimensions và audio duration. Video là bundle atomic gồm
  primary + poster ảnh bắt buộc. File lớn đi thẳng browser → R2, không qua body
  Vercel Function.
- Presign/complete/cancel đều cần session; mutation Origin phải khớp `AUTH_URL`.
  Service kiểm role hiện tại tại complete/cancel và trả 404 cho intent khác owner.
  Conditional state transition chặn complete/cancel race và giữ complete idempotent.
- Slot 1..10 được reserve trong Serializable transaction + unique constraint để
  chặn request đồng thời. Slot chỉ release sau physical delete thành công; cleanup
  lỗi giữ slot và cancel retry tiếp tục cleanup.
- Ba Route Handlers Node.js: `POST /api/upload/presign`,
  `POST /api/upload/complete`, `DELETE /api/upload/[uploadId]`. P3-09 chỉ trả
  validated durable reference; P3-10/13/15/16 mới claim vào Story/AudioAsset/
  BackgroundAsset trong transaction nghiệp vụ và triển khai UI tương ứng.

Thiết kế dùng direct upload vì Vercel giới hạn request/response Function 4.5 MB;
R2 Standard có free tier 10 GB-month, không tính egress, và Cloudflare khuyến nghị
single PUT cho file nhỏ/trung bình dưới khoảng 100 MB. Nguồn:
[R2 pricing](https://developers.cloudflare.com/r2/pricing/),
[upload objects](https://developers.cloudflare.com/r2/objects/upload-objects/),
[presigned URLs](https://developers.cloudflare.com/r2/api/s3/presigned-urls/),
[S3 compatibility](https://developers.cloudflare.com/r2/api/s3/api/),
[bucket naming](https://developers.cloudflare.com/r2/buckets/create-buckets/),
[R2 CORS](https://developers.cloudflare.com/r2/buckets/cors/),
[Vercel Functions limits](https://vercel.com/docs/functions/limitations).

Trong quá trình phát triển, migration tạo table đã được apply trước khi bổ sung state
`PROCESSING`. Vì không sửa migration đã apply, state được đặt vào migration additive
kế tiếp. Lần chạy đầu của migration thứ hai đã thực thi `ALTER TYPE` nhưng runner chưa
ghi nhận hoàn tất; đã xác minh enum thực tế rồi dùng `prisma migrate resolve --applied`.
Trạng thái cuối cùng `migrate status` up to date; đường chạy clean vẫn gồm hai migration
theo thứ tự. Việc deploy đường chạy clean trên PostgreSQL tạm sẽ được CI database job
kiểm tra sau push.

- Domain claim/UI chưa thuộc stage này: Story cover P3-10, Admin Background P3-13,
  AudioAsset P3-15, personal image/video+poster ScenePicker P3-16.

  snapshots giữ durable URL. Không release video slot chỉ vì DB asset bị ẩn/xóa.

## Rollback

Hai migration chỉ thêm enum/table/relation và không đổi dữ liệu Story/Scene hiện có.
Nếu rollback deployment, giữ bảng/intents và R2 objects, tắt consumer route bằng bản
app trước rồi forward-fix; không drop enum/table hoặc xóa object hàng loạt. Chỉ cleanup
object sau reference audit. Presigned URL đã phát tự hết hạn tối đa sau 10 phút.

## Phạm vi đã triển khai

- Migration additive, non-null `Story.authorDisplayName`; P3-04 migration map byline JSON vào
  trường này và verify chính xác. `authorId` tiếp tục là ownership ổn định; repository chỉ map
  `authorDisplayName → Story.author`, không suy byline từ tên/email của User.
- Prisma read repositories cho public/full Story, chapter Reader aggregate, Scene snapshot,
  active global background/palette/preset và Effect overlay/keyword. Mapper chỉ trả domain
  contract, không expose Prisma row hoặc khóa chính nội bộ.
- Public Story/Chapter lọc `published`, xác minh chapter thuộc đúng Story và navigation chỉ dùng
  published order. `getAllForAuthor` lọc bằng `authorId` đã migrate.
- Scene/catalog JSON columns đi qua codec/Zod; snapshot/range/overlap/catalog hỏng fail có mã
  observability và không resolve ngược catalog. Event chỉ có `level`, `code`, `count`.
- Story/Scene read selector và shadow flag được validate server-side. Mặc định vẫn JSON;
  Prisma write vẫn bị từ chối. Shadow trả kết quả primary, so normalized output, bỏ qua ownership
  query không thể đối chiếu an toàn từ JSON và không log content/token/selector/connection.
- CI chạy thêm `test:reads:db`. `db:check-empty` chuyển sang TypeScript runner CommonJS hiện có,
  loại bỏ lỗi Node 24 Linux ESM khi resolve nested extensionless import; không đổi toàn package
  sang ESM.

## Rollback

Giữ các read/shadow flags ở mặc định JSON để rollback traffic đọc. Migration
`authorDisplayName` là additive và đã deploy trên Neon dev: không drop cột để rollback code;
forward-fix nếu cần. JSON vẫn là canonical write path cho đến controlled cutover, nhưng sau khi
Prisma write được bật ở stage sau phải dùng DB backup/PITR theo runbook, không quay lại JSON làm
nguồn rollback.

## Audio implementation

- App-token search, 600 ms debounce, bounded per-instance 10-minute cache and 12/minute bucket;
  transaction advisory lock prevents simultaneous search upstream calls per author across instances.
  Burst bucket is per-instance, not a globally durable minute counter.
- Separate OAuth popup, state cookie bound to actor with authenticated encryption, token refresh
  under row lock, disconnect clears credentials and preserves assets. No credential projection.
- Personal upload reuses presign/direct PUT/complete then atomic asset claim; upload ID is asset
  ID for retries. MP3/WAV/OGG, 8 MiB, 5 minutes; fixed an unsigned MPEG sync-mask bug exposed by spike.
- Import reserve/download/normalize/R2/save/settle; reuse and unique-race reconciliation; safe
  cleanup avoids deleting a possibly committed immutable URL.
- Shared picker in block and Scene audio; profile integration for author/admin; attribution
  projects only audio references from the already authorized/public chapter and both ambient/block effects.

## Transcoding spike

Candidate pinned `ffmpeg-static@5.3.0` (binary release b6.1.1), binary fetched by the explicitly
allowlisted pnpm install script. Original baseline: no shell invocation; pipe-only FFmpeg protocols, allowed audio
demuxers, 45-second child timeout, output cap. Input download bounded to 64 MiB.

Local Windows x64 / Node 24.20.0 fixture: PCM WAV stereo 48 kHz, 299 seconds, 57,408,044 bytes.
Three runs: **5,043 / 3,970 / 3,945 ms**, output **4,784,841 bytes**, parsed **299,050 ms**;
binary **82,797,568 bytes**, sampled parent RSS **163,291,136 bytes** (not child peak RSS).
Three samples are not a p95 benchmark. The real MP3 fixture exposed and verified the MPEG mask fix.

Local Windows Next.js traces include the binary: import **257,690,921 bytes** and spike
**256,287,933 bytes** (sum of traced files, not Vercel's final Linux deployment size).
This is close to the documented 250 MB limit, so Linux bundle verification is mandatory;
do not claim the candidate is deployment-ready from the Windows build alone.

Vercel gate remains required before finalizing the candidate: run admin-only POST
`/api/admin/audio-transcode-spike` with same-origin authenticated admin; record Linux binary
availability, cold/warm timing, memory and traced bundle size. Route returns metrics only,
never generated media bytes. Remove the temporary spike route after recording deployment evidence.

## M4A/AAC follow-up — 2026-09-21

Freesound normalization now accepts AAC ADTS and M4A. M4A `ftyp` inputs use a unique
temporary directory and fixed private filename (no provider filename), seekable local input,
`mov` demuxer, disabled external data references and no network protocols. Other formats
stay on pipes. Cleanup runs in finally after child completion. Abrupt process termination
can bypass finally; no new cleanup job is introduced. Maximum temporary input is 64 MiB
per concurrent M4A conversion; existing input/output/duration/time limits remain.

`pnpm test:audio:transcode` passed locally on Windows / Node 24 with generated real media:
M4A moov at end and faststart, AAC ADTS, WAV/MP3/OGG/FLAC/AIFF regression and MP3 decoding,
parallel conversions, malformed input, playlist rejection, >64 MiB and >5-minute rejection,
299-second acceptance and temporary file cleanup. Added the command to Linux CI.
Linux CI/Vercel runtime and actual personal Freesound imports have not been run here.
Typecheck, targeted ESLint, unit suite and production build passed. Sandbox build initially
failed fetching Google Fonts; the approved retry outside the sandbox passed.
FFmpeg references: [protocols](https://ffmpeg.org/ffmpeg-protocols.html),
[MOV options](https://ffmpeg.org/ffmpeg-formats.html#mov_002fmp4_002f3gp).
